# AiFiction 系统设计

最后更新：2026-03-27

## 1. 设计目标

当前系统目标不是构建一个先天自治的 Agent 群，而是先把“长篇小说的结构化控制底座”搭稳：
- 本地正文持续推进
- 自动维护优先
- 人工主要负责审查与判断
- 数据、流程、提示词和运行轨迹都可追踪

## 2. 分层设计

### 2.1 `packages/schemas`
负责领域契约与结构化 schema，是作品、角色、章节、状态等对象的统一接口层。

### 2.2 `packages/data`
负责持久化与查询，是当前项目的核心数据底座。当前已经拆成：
- V2 项目目录层
- V2 叙事资产层
- V2 运行产物层
- V2 自动同步层
- workbench 读写服务层

### 2.3 `packages/core` / `packages/prompts`
负责工作流组装、prompt 模板和后续生成阶段的上下文组织。

### 2.4 `apps/worker`
负责后台任务入口。当前除章节预览链外，还提供目录同步 CLI 入口。

### 2.5 `apps/web`
负责工作台界面。当前页面已经从“重手工录入”向“自动维护 + 待审查 + 手工兜底”收口。

## 3. 真相源设计

系统当前采用 4 层真相分工：
- 本地正文层：本地目录中的正文、大纲、导出物
- 结构化资产层：作品、角色、关系、卷章、伏笔、时间线等核心事实
- 运行产物层：摘要预览、抽取预览、artifact、run log、snapshot
- 审查层：`asset_updates_v2` 和 `review_queue_v2` 中的建议更新与待判断项

核心原则：
- 不依赖把整本正文硬塞进 prompt 里维持长期记忆。
- 长期记忆由系统维护，不由模型“硬记”。
- AI 主要处理新增或修改章节带来的增量变化。
- 高风险改动先进入审查，不直接覆盖事实层。

## 4. V2 数据底座是否足够

结论：足够，当前不需要推倒重来。

当前 V2 已具备 4 类核心能力：
- 项目目录：作品与 profile
- 叙事资产：角色、关系、卷章、伏笔、时间线
- 运行产物：artifact、version、run、snapshot
- 自动同步：file source、source document、review queue、source refs

后续再迭代，主要是继续加读模型、服务层、辅助表和处理规则，不是重建主 schema。

## 5. 当前主链

当前已经落地的链路如下：
1. 绑定作品本地目录
2. 扫描目录下的章节 / 大纲 / 导出文件
3. 生成摘要预览与结构化抽取预览
4. 写入待审查项与来源引用
5. 在工作台中按“变更包”进行审查
6. 把通过的候选回写到结构化事实层

## 6. 当前抽取与回写策略

当前“摘要 + 抽取”还不是最终版模型抽取器，而是一个稳定的首版接口：
- 先把同步、审查、回写主链跑通
- 再逐步把启发式预览替换成更真实的模型抽取

当前已覆盖的候选预览：
- 角色
- 关系
- 伏笔
- 时间线

当前已正式写回事实层：
- 角色候选
- 关系候选
- 伏笔候选
- 时间线候选

## 7. 当前 UI 收口原则

当前工作台的方向不是“让用户填满后台”，而是：
- 首页先找书、看状态、继续处理
- 详情页先看总览和待处理，再按需下钻
- 手工维护只作为兜底入口

详情页当前分为：
- 总览
- 待处理
- 剧情资产
- 高级维护

## 8. 当前最紧急的问题

当前最紧急的问题不是继续补底层能力，而是继续降低人工占比：
- 审查机制还要继续收口
- 冲突处理还要补强
- 低风险自动通过还要再扩大覆盖范围
- 影响分析还要继续升级为更明确的处理动作

因此当前优先级应调整为：
1. 强化来源引用与冲突处理
2. 扩大低风险自动通过
3. 让影响分析更可执行
4. 最后再推进更真实的模型抽取与关系图谱

## 9. 机器上下文层

- 仓库新增了一层“机器上下文”配置，用来承接不同电脑上的路径、SSH、Git 安全目录和本地端口差异。
- 机器上下文的读取顺序是：`config/machine-profiles.json` -> `config/machine-overrides.local.json` -> 运行时探测。
- 这一层不参与业务事实建模，只服务于本地开发执行链，避免把电脑差异硬编码进 skill、文档或临时命令。

## 10. 编码稳定性策略

- 仓库文本文件统一使用 UTF-8 与 LF，编辑器侧通过 `.editorconfig` 和 `.vscode/settings.json` 固定编码。
- 对中文内容的批量更新，优先使用显式 UTF-8 写入方式，不依赖 PowerShell 默认输出编码。
- `scripts/encoding-check.mjs` 负责在提交前发现明显的问号污染、替换字符和常见乱码信号。
