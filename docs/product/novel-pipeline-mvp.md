# 网文流水线 MVP 设计

## 1. 项目定位

这个项目的定位不是“自动写网文的黑盒”，而是“个人网文创作操作系统”。

核心价值：

- 帮你把一本长篇小说拆成稳定可复用的步骤。
- 帮你沉淀可复用的创作资产，而不是每本书都从零开始。
- 帮你在长周期创作中维持设定一致、人物稳定、主线不偏。
- 帮你把 AI 从“偶尔灵感工具”变成“可调度的生产环节”。

## 2. 产品边界

首版产品不追求完全自治，也不追求多 Agent 自组织。

首版只做这三件事：

1. 结构化管理作品资产
2. 让章节生成进入固定流水线
3. 让每一章写完后都能回写状态和记忆

不在 MVP 内的能力：

- 自动联网采风
- 自动发布到平台
- 完整多模型路由平台
- 多作者协作系统
- 大规模向量检索平台

## 3. 作品的控制单位

不要把“章节”当成唯一控制单位。

更合理的控制层级：

- 作品：商业定位、题材、平台、目标字数、更新节奏、风格边界
- 卷：阶段目标、核心冲突、主要升级、阶段悬念
- 章：本章功能、冲突、信息推进、结尾钩子
- 场景：动作、信息、情绪、人物关系变化

一个常见误区是只维护章节正文，而不维护“卷级目标”和“角色状态变化”。
长篇小说偏轨，往往就是从这里开始的。

## 4. 建议的数据资产

每本书至少维护以下资产：

- 作品定位卡
- 风格卡
- 世界规则清单
- 角色卡
- 角色状态快照
- 全书大纲
- 分卷大纲
- 章节卡
- 时间线事件表
- 伏笔账本
- 审校报告
- 运行日志

其中最关键的是两类：

- 静态资产：设定、规则、人物底层性格、风格边界
- 动态资产：人物当前知道什么、失去了什么、关系怎么变了、伏笔是否已经回收

## 5. 首版流水线

建议按下面顺序执行，不要跳步：

1. 作品定位卡
2. 世界观与角色圣经
3. 全书大纲
4. 分卷大纲
5. 章节卡
6. 章节初稿
7. 连续性检查
8. 风格润色
9. 人工确认
10. 状态回写

每一步都必须满足三个条件：

- 输入明确
- 输出结构化
- 结果可重跑

## 6. 如何防止写偏

要防止模型越写越偏，不能只靠大 prompt。

需要同时建立 5 种约束：

- 不变量约束：世界规则、力量体系、角色底层性格不可随意改变
- 章节目标约束：本章要完成什么必须提前定义
- 上下文约束：只注入与当前任务相关的信息
- 审核闸门约束：不通过检查不能流入下一步
- 回写约束：每章写完必须更新记忆和状态

## 7. 上下文与记忆策略

不要试图把整本书的正文一直塞进模型上下文。

推荐做分层上下文：

- 固定层：作品定位卡、风格卡、核心设定
- 当前层：当前卷摘要、最近章节摘要、当前章节卡
- 检索层：相关角色状态、相关地点、相关伏笔、相关规则
- 临时层：本次任务的特殊要求

真正应该长期保存的不是全文上下文，而是“可检索的知识单元”。

例如：

- 角色知道什么
- 角色当前情绪和关系变化
- 事件发生在第几天
- 某个伏笔埋在第几章，计划在哪一卷回收

## 8. 文风策略

建议“单书统一，跨书可变”。

也就是说：

- 每本书保持主风格稳定
- 不同题材允许切换风格模板
- 同一本书内部只允许场景级微调，不建议根风格频繁变化

风格卡建议维护：

- 叙事视角
- 语言密度
- 节奏强度
- 情绪浓度
- 对话占比
- 爽点频率
- 禁止出现的表达习惯

## 9. 数据存储建议

如果你是自用 MVP，有两种实际可行的路：

### 路线 A：先轻量起步

- 主数据库：SQLite
- 运行产物：文件系统
- 适合快速验证流程

### 路线 B：直接面向演进

- 主数据库：PostgreSQL
- 半结构化结果：JSONB
- 文件产物：对象存储或本地 artifacts 目录
- 后续检索：按需引入 pgvector

如果你已经确定后面会扩成长期项目，建议直接走 PostgreSQL。

## 10. Agent 策略

首版不要先做“大总管 Agent”。

更合理的路径：

- 第 1 阶段：工作流 + 结构化输出
- 第 2 阶段：给单个环节配专用 agent
- 第 3 阶段：必要时再做环节之间的 handoff

优先值得 agent 化的环节：

- 大纲拆分
- 连续性检查
- 风格润色

## 11. 关键指标

你后面需要持续观察这些指标：

- 每章平均返工次数
- 章节生成成本
- 一致性错误次数
- 人工修改比例
- 伏笔遗失率
- 章节完成耗时

## 12. 第一阶段里程碑

### 里程碑 1

- 能创建作品
- 能维护角色卡 / 设定卡
- 能生成全书大纲和分卷大纲

### 里程碑 2

- 能维护章节卡
- 能按章节卡生成初稿
- 能输出连续性检查报告

### 里程碑 3

- 能更新角色状态、时间线、伏笔账本
- 能查看章节生成链路和版本差异
