# AiFiction 项目进度

最后更新：2026-03-27

## 1. 当前项目目标

当前项目目标已经收敛为：构建一个“本地正文驱动、自动维护优先、人工审查兜底”的个人网文控制台。

这意味着：
- 不再把重点放在手工录入型后台。
- 不把重点放在一开始就做复杂 Agent 协作。
- 优先把数据底座、增量同步、自动维护和审查机制做稳。

## 2. 当前阶段

当前阶段：**阶段 4.5：产品收口与自动化减负**

阶段判断：
- V2 数据底座还能继续承接后续改造，不需要推倒重来。
- 自动同步、待审查和首版事实回写已经接进 Web 工作台。
- 首页书架化和详情页分区化已完成第一轮收口。
- 当前最紧急的问题已经转向审查机制、冲突处理和降低人工占比。

## 3. 已完成内容

### 3.1 数据与同步底座
- SQLite 已接入。
- V2 schema 已落地。
- 自动同步相关表已进入 schema 与 migration。
- `db:v2-smoke`、`db:sync-smoke`、`db:workbench-smoke` 可以作为主验证入口。

### 3.2 自动同步主链
- 已支持绑定作品本地目录。
- 已支持扫描新增 / 修改文件。
- 已支持为源文件生成摘要预览和抽取预览。
- 已支持写入 `asset_updates_v2` 和 `review_queue_v2`。
- 已支持对审查项执行“通过 / 驳回”。
- 已支持把通过的角色、关系、伏笔、时间线候选写回事实层。

### 3.3 Web 工作台
- 首页已重构为书架 + 搜索 + 快速创建入口。
- 作品详情页已拆为“总览 / 待处理 / 剧情资产 / 高级维护”。
- 待处理已切为“变更包”视图，而不是单条 review item 堆叠。
- 低风险自动通过入口已落地。
- 影响分析已开始接入待处理视图。

## 4. 当前未完成的关键项

- 继续强化来源引用与冲突处理。
- 继续压缩人工维护入口，让低风险项更多自动处理。
- 把影响分析进一步升级成可执行的动作分发。
- 把关系图谱和后续影响分析逐步接进工作台。

## 5. 下一阶段建议顺序

1. 补强来源引用和冲突处理。
2. 继续做低风险自动通过与中高风险分流。
3. 把影响分析接成更清晰的处理动作。
4. 再推进关系图谱和更真实的模型抽取。

## 6. 机器配置收口

- 已新增 `config/machine-profiles.json`，按电脑信息或工作区路径匹配当前机器。
- 已新增 `scripts/machine-context.mjs` 与 `npm.cmd run machine:context` 入口。
- Skill 不再依赖固定盘符路径，后续优先读取机器上下文再执行本地命令。
- 已预留 `config/machine-overrides.local.json` 本地覆盖方案，便于多电脑切换。

## 7. 编码稳定性收口

- 已新增 `.editorconfig`、`.vscode/settings.json` 和 `scripts/encoding-check.mjs`。
- 中文文档和页面文案后续统一按 UTF-8 写入，避免再次出现整段 `?` 或 mojibake 污染。
- 新的默认校验链是：先跑 `npm.cmd run encoding:check`，再跑 `npm.cmd run typecheck`。
