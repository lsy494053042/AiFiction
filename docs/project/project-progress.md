# AiFiction 项目进度

最后更新：2026-03-27

## 1. 当前项目目标

当前项目目标已经收敛为：构建一个“本地正文驱动、自动维护优先、人工审查兜底”的个人网文控制台。

这意味着：
- 不再把重点放在手工录入型后台。
- 不把重点放在一开始就做复杂 Agent 协作。
- 优先把数据底座、增量同步、自动维护和审查机制做稳。

## 2. 当前阶段

当前阶段：**阶段 4.5：产品收口与自动化减负**

阶段判断：
- V2 数据底座还能继续承接后续改造，不需要推倒重来。
- 自动同步、待审查和首版事实回写已经接进 Web 工作台。
- 首页书架化和详情页分区化已完成第一轮收口。
- 当前最紧急的问题已经转向审查机制、冲突处理和降低人工占比。

## 3. 已完成内容

### 3.1 数据与同步底座
- SQLite 已接入。
- V2 schema 已落地。
- 自动同步相关表已进入 schema 与 migration。
- `db:v2-smoke`、`db:sync-smoke`、`db:workbench-smoke` 可以作为主验证入口。

### 3.2 自动同步主链
- 已支持绑定作品本地目录。
- 已支持扫描新增 / 修改文件。
- 已支持为源文件生成摘要预览和抽取预览。
- 已支持写入 `asset_updates_v2` 和 `review_queue_v2`。
- 已支持对审查项执行“通过 / 驳回”。
- 已支持把通过的角色、关系、伏笔、时间线候选写回事实层。

### 3.3 Web 工作台
- 首页已重构为书架 + 搜索 + 快速创建入口。
- 作品详情页已拆为“总览 / 待处理 / 剧情资产 / 高级维护”。
- 待处理已切为“变更包”视图，而不是单条 review item 堆叠。
- 低风险自动通过入口已落地。
- 影响分析已开始接入待处理视图。

## 4. 当前未完成的关键项

- 继续强化来源引用与冲突处理。
- 继续压缩人工维护入口，让低风险项更多自动处理。
- 把影响分析进一步升级成可执行的动作分发。
- 把关系图谱和后续影响分析逐步接进工作台。

## 5. 下一阶段建议顺序

1. 补强来源引用和冲突处理。
2. 继续做低风险自动通过与中高风险分流。
3. 把影响分析接成更清晰的处理动作。
4. 再推进关系图谱和更真实的模型抽取。

## 6. 机器配置收口

- 已新增 `config/machine-profiles.json`，按电脑信息或工作区路径匹配当前机器。
- 已新增 `scripts/machine-context.mjs` 与 `npm.cmd run machine:context` 入口。
- Skill 不再依赖固定盘符路径，后续优先读取机器上下文再执行本地命令。
- 已预留 `config/machine-overrides.local.json` 本地覆盖方案，便于多电脑切换。

## 7. 编码稳定性收口

- 已新增 `.editorconfig`、`.vscode/settings.json` 和 `scripts/encoding-check.mjs`。
- 中文文档和页面文案后续统一按 UTF-8 写入，避免再次出现整段 `?` 或 mojibake 污染。
- 新的默认校验链是：先跑 `npm.cmd run encoding:check`，再跑 `npm.cmd run typecheck`。

### 自动分流（2026-03-28）
- 已落地项目级自动分流：低风险审查项自动通过，其余项继续留在待处理区。
- reviewStats 已增加自动接收 / 需要复核 / 冲突 3 类计数。
- 当前下一优先级：把自动分流继续扩展为更细的冲突处理策略和更明确的后续动作。

### 阶段 4.6 第二轮（2026-03-28）
- 待处理页已改成三段式分流：自动接收、需要复核、冲突处理。
- 变更包新增明确处理策略，信息缺口与事实冲突不再只靠风险级别表达。
- 作品详情页的焦点引导已经切到“先冲突、再复核、最后自动清理低风险”的顺序。

### 阶段 4.6 第三轮（2026-03-28）
- 影响分析已升级为“建议复核章节”输出，并在项目级读模型里做了聚合。
- reviewStats 已拆出信息缺口、事实冲突、格式阻塞、置信度复核四类风险计数。
- 待处理页和详情页都已接入建议复核章节，用于提示后续章节的连贯性回看。

## 阶段 4.6 第四轮（2026-03-28）
- 已把“建议复核章节”升级为两档动作：`正式复核`、`提醒回看`。
- 项目级读模型已新增相关统计：`formalReviewChapterCount`、`watchChapterCount`。
- 待处理页和作品详情页已同步显示这两档章节，不再只给一个笼统的建议复核总数。

## 阶段 4.6 第五轮（2026-03-28）
- 已把正式复核章节提升为详情页里的独立后续处理块。
- 总览焦点现在会优先提示“正式复核章节”，而不是把它继续埋在普通统计里。
- 当前主链保持不变：目录同步 -> 抽取 -> 变更包 -> 风险分流 -> 后续章节分流。

## 阶段 4.6 第六轮（2026-03-28）
- 已把正式复核章节提升为任务对象，并在作品详情页按任务渲染。
- follow-up queue 现在提供 formalReviewTasks，方便后续接章节级复核动作。

## 阶段 4.6 第七轮（2026-03-28）
- 已为正式复核任务新增持久化状态层，对应数据库表为 `follow_up_task_states_v2`。
- `followUpQueue` 现在会合并持久化状态，已完成或本轮跳过的正式复核任务不再继续占用活跃队列。
- 详情页已接入“标记已复核 / 本轮跳过”入口，这一层开始具备真正的任务状态流转。
- 当前下一优先级：在此基础上推进关系图谱页和更清晰的来源引用展示。

## 阶段 4.6 第八轮（2026-03-28）
- 作品详情页新增 `graph` 视图，把“关系图谱”从剧情资产页中独立拆出。
- 第一版图谱视图已能单独查看角色节点覆盖度、关系事实排序与最近来源引用。
- 当前下一优先级：继续把来源引用和关系图谱做得更可点击、更可追踪。

- 图谱页支持按角色和来源类型筛选，并通过 URL 保留当前筛选状态。
- 已打通图谱来源追踪：从关系边或来源引用可以直接进入对应来源的待处理变更包。
- 正式复核任务已从单纯状态推进为结果闭环：可提交结果、可落库、可显示最近处理记录，并支持重新打开。

## 最新进展（2026-03-28 / 自动维护链闭环）
- 扫描完成后，系统会自动分流本次 sync run 内的审查项，不再把历史待处理项一起卷入当前同步。
- 低风险项会自动审批，并继续走现有事实回写链。
- 高风险项保持在待处理区，人工只需处理剩余冲突与复核任务。
- 按主线口径，「来源追踪闭环 / 复核机制闭环 / 自动维护链闭环」三步已完成，项目达到首个可自用闭环。
