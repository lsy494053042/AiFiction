# 小说领域模型说明

## 1. 设计原则

- 一本书的事实必须可回溯。
- 设定、角色、剧情、状态、审校是不同层级的数据。
- 动态状态不能只写在正文里，必须单独存。
- Prompt 和模型输出需要版本化，便于复盘质量变化。

## 2. 核心实体

### WorkProfile

表示一本书的顶层定位。

关键内容：

- 书名、别名、题材、平台
- 目标读者
- 一句话卖点
- 目标字数
- 更新节奏
- 禁忌边界

### StyleProfile

表示一本书的主风格边界。

关键内容：

- 叙事视角
- 语言密度
- 情绪强度
- 对话占比
- 节奏偏好
- 禁止表达

### CharacterCard

表示角色静态设定。

关键内容：

- 公开身份 / 隐藏身份
- 核心欲望 / 核心恐惧
- 关键秘密
- 关系网络
- 人物成长弧

### CharacterStateSnapshot

表示角色在某一章节后的动态状态。

关键内容：

- 当前知道的信息
- 当前持有的资源
- 当前伤势 / 限制
- 与其他角色关系变化
- 当前未解决的问题

### VolumeOutline / ChapterCard / SceneCard

这三层用于把小说从全书拆到卷、章、场景。

建议先做卷和章，场景层后补。

### ForeshadowLedgerItem

用于跟踪伏笔。

关键内容：

- 埋点章节
- 伏笔意图
- 当前状态
- 预计回收点
- 实际回收点

### TimelineEvent

用于跟踪世界内时间。

关键内容：

- 发生时间
- 涉及角色
- 事件影响
- 关联章节

### PipelineRun

用于记录一次工作流运行。

关键内容：

- 运行阶段
- 输入摘要
- 输出摘要
- 成本
- 模型
- 是否成功
- 错误信息

## 3. 持久化建议

推荐把数据分三层保存：

### 主数据

放数据库。

包括：

- 作品
- 角色卡
- 卷纲 / 章纲
- 角色状态
- 时间线
- 伏笔账本
- 运行记录

### 运行产物

放文件系统或对象存储。

包括：

- 原始模型响应
- Prompt 快照
- 草稿版本
- 审校报告
- 导出文件

### 检索摘要

放数据库的 JSONB 或后续向量扩展中。

包括：

- 章节摘要
- 人物状态摘要
- 规则摘要
- 冲突摘要

## 4. 为什么不只存全文

因为全文不适合作为可控记忆。

只存全文会带来这些问题：

- 检索成本高
- 模型容易抓错重点
- 无法显式校验规则
- 无法直接统计角色或伏笔变化

所以更推荐“正文 + 结构化事实”双轨保存。
