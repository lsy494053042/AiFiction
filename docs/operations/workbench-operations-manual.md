# AiFiction 操作手册

最后更新：2026-03-27

## 1. 当前可用功能

### 1.1 Web 工作台
- 首页已经改成“导航 + 书架 / 列表 + 搜索”的工作台入口，不再用大面积介绍卡占首屏。
- 作品详情页已经拆成 4 个视图：
  - 总览
  - 待处理
  - 剧情资产
  - 高级维护
- 手工维护仍然保留，但已经收口到“高级维护”里，只作为补录和纠错入口。

### 1.2 自动同步
- 可为作品绑定本地目录。
- 绑定后会立即执行首轮扫描。
- 可对已绑定目录执行重新扫描。
- 扫描命中新文件或修改文件后，会生成摘要预览、抽取预览、建议更新和待审查项。

### 1.3 审查机制
- 可直接在作品详情页对待审查项执行“通过 / 驳回”。
- 待审查当前以“变更包”形式展示，而不是零散条目。
- 审查结果会同步写回：
  - `review_queue_v2`
  - `asset_updates_v2`
  - `source_documents_v2.syncStatus`
- 当前已经支持把通过的角色、关系、伏笔、时间线候选写回事实层。

## 2. 推荐使用顺序

1. 先运行 `npm.cmd run machine:context`
2. 再运行 `npm.cmd run db:v2-smoke`
3. 需要同步链路验证时运行 `npm.cmd run db:sync-smoke`
4. 启动 `npm.cmd run dev:web`
5. 进入某本作品详情页，先看“总览”视图
6. 如果还没绑定目录，切到“待处理”视图绑定本地目录
7. 扫描完成后，继续在“待处理”里处理“通过 / 驳回”
8. 切到“剧情资产”视图，检查分卷、角色、章节和关系是否成形
9. 只有自动维护明显不够时，才进入“高级维护”补录或修正

## 3. 当前自动同步会做什么

扫描命中新文件或修改文件后，当前会继续执行：
- 读取 `.md` / `.txt`
- 生成摘要预览 artifact
- 生成结构化抽取预览 artifact
- 写入 `asset_updates_v2`
- 写入 `review_queue_v2`
- 写入 `source_refs_v2`

当前 `.docx` 还不会自动解析正文，而是先进入待审查队列，等待后续接入专门解析器。

## 4. 当前事实回写范围

已经能正式写回事实层的候选：
- 角色候选
- 关系候选
- 伏笔候选
- 时间线候选

`db:sync-smoke` 已经覆盖“扫描 -> 审查通过 -> 事实回写”的验证链。

## 5. 目录绑定与路径规则

- 默认数据库路径：`storage/db/aifiction.sqlite`
- `rootPath` 如果填相对路径，会按工作区根目录解析。
- `chapterPath`、`outlinePath`、`exportPath` 如果填相对路径，会按作品根目录解析。
- 当前扫描默认包含：`.md`、`.txt`、`.docx`
- 当前扫描默认排除：`.git`、`.next`、`dist`、`node_modules`

## 7. 机器上下文

- 新机器接入时，先执行 `node scripts/machine-context.mjs` 或 `npm.cmd run machine:context`。
- 输出里需要确认这几项：
  - `workspaceRoot`
  - `git.safeDirectory`
  - `git.remoteUrl`
  - `ssh.host`
  - `web.preferredPort`
  - `storage.databasePath`
- 如果当前电脑和仓库内置配置不完全一致，就复制 `config/machine-overrides.local.example.json` 为 `config/machine-overrides.local.json`，只改本机差异项。
- 如果 PowerShell 因执行策略拦截 `npm`，直接改用 `npm.cmd`，不要把这个问题误判成仓库脚本故障。
- 沙箱审批属于运行环境边界，不能靠 skill 彻底关闭；能做的是尽量复用稳定脚本入口，例如 `npm.cmd run typecheck`、`npm.cmd run db:sync-smoke`、`npm.cmd run db:workbench-smoke`。

## 8. 中文与编码

- 中文文档、页面文案、配置说明统一按 UTF-8 写入，不使用依赖终端默认编码的重定向写法。
- 仓库已增加 `.editorconfig`、`.vscode/settings.json` 和 `scripts/encoding-check.mjs`，用于固定 UTF-8 读写和巡检乱码。
- 后续只要批量改过中文内容，先跑 `npm.cmd run encoding:check`，再跑 `npm.cmd run typecheck`。

### 自动分流（2026-03-28）
- 在“待处理 / 变更包”区域，优先使用“自动分流并清理低风险”。
- 这个动作会自动清掉低风险项，只把需要你判断的复核包和冲突包留在页面上。

## 变更包分流（2026-03-28）
- 待处理页现在默认按三类展示：自动接收、需要复核、冲突处理。
- 如果顶部出现“自动处理低风险变更包”按钮，说明当前有可直接清理的低风险包，优先点这一项。
- 冲突包需要先看原文证据和既有事实层，再决定是否整包通过。

## 建议复核章节（2026-03-28）
- 如果待处理页或作品详情页出现“建议复核章节”，说明当前变更包已经可能影响这些后续章节。
- 这些章节不是强制修改清单，而是系统给出的优先回看名单。
- 一般顺序是：先处理冲突包，再看需要复核的包，最后顺手检查建议复核章节。

## 正式复核章节与提醒回看章节（2026-03-28）
- 如果系统把后续章节标成“正式复核”，说明它已经被冲突包、事实冲突或多次重复触发命中，优先级更高。
- 如果系统把后续章节标成“提醒回看”，说明当前更适合先处理眼前的变更包，随后顺手检查这些章节是否出现连锁偏移。
- 建议顺序是：先处理冲突包，再处理需要复核的包，最后看正式复核章节，提醒回看章节放在最后。

## 正式复核队列（2026-03-28）
- 如果作品详情页出现“正式复核队列”，说明这些后续章节已经不再只是提醒回看，而是建议你真正进入复核。
- 操作顺序仍然是：先冲突包，再需要复核的变更包，然后处理正式复核章节，最后再看提醒回看章节。

## 正式复核任务（2026-03-28）
- 作品详情页里的“正式复核队列”现在展示的是章节级任务，而不是单纯的章节提示。
- 这些任务的意义是把真正需要回看的章节从提醒回看里抬出来，避免它们混在普通提示中。

## 正式复核任务操作（2026-03-28）
- 在作品详情页的“正式复核队列”里，现在可以直接对任务执行“标记已复核”或“本轮跳过”。
- “标记已复核”会将当前任务指纹记录为已完成，该任务不再继续占用队列。
- “本轮跳过”会从当前活跃队列中移除该任务，但当系统后续识别到新的任务指纹时，它会重新出现。
- 处理备注是可选的，但建议在给出人工判断时顺手记一句，方便后续回看。

## 关系图谱视图（2026-03-28）
- 在作品详情页导航中新增了“关系图谱”入口。
- 这个视图会把角色网络、关系事实和最近来源引用拆开查看，适合在你想快速判断“谁与谁的关系现在是怎样”时使用。

- 在作品详情的“关系图谱”页，可以按角色或来源类型收缩图谱，方便快速定位局部关系网络。
- 在关系图谱页点击“查看同源变更”后，会直接跳到待处理页并按对应来源过滤。
- 在作品详情的正式复核队列里，现在可以直接提交处理结果，系统会记录最近处理结果，并支持重新打开任务。

## 扫描后自动分流规则（2026-03-28）
- 目录重扫后，系统会先生成摘要预览、抽取预览和 review item。
- 同一次 sync run 内的低风险 review item 会被自动通过，并继续走事实回写。
- 只有剩余的高风险项会留在工作台里等你处理。
