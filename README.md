# AiFiction

AiFiction 是一个面向个人长篇网文创作的工作台。

它现在的定位不是“全自动写书系统”，而是：

- 你在 `VSCode + Codex` 里创作
- 本地目录保存设定、大纲、正文
- 协议文件负责告诉系统“这本书在哪、现在写到哪”
- 数据库负责保存结构化状态和写作知识
- 网页工作台负责查看作品与处理少量例外

一句话：

**文件负责创作，协议负责定位，数据库负责结构化控制，工作台负责查看和处理例外。**

## 项目怎么工作

### 1. 创作文件层

真正的创作内容都在：

```text
books/作品名/
  00-设定/
  01-大纲/
  02-正文/
  03-中间产物/
```

这些文件是作品内容真相源。

### 2. 协议锚点层

核心文件：

- `workspace.yml`
- `books/作品名/book.yml`

它们只负责：

- 当前有哪些书
- 当前激活哪本书
- 当前写到哪一卷哪一章
- 当前批次、gate、止损线、知识流程状态

### 3. 数据库层

当前是本地 SQLite。

数据库不保存完整正文，主要负责：

- 角色、别名、关系、伏笔、时间线
- 同步 run、待处理项、来源引用
- 批次复盘
- 候选经验、规则状态、profile、应用记录、gate 结果

### 4. 工作台层

网页工作台负责：

- 书架
- 单书视图
- 工作区阅读
- 待处理例外

## 数据库在这里到底起什么作用

数据库不是用来“替代写作文件”的。

它主要做三件事：

1. 把小说拆成可查询的结构化状态
2. 记录同步、复盘、规则升级、gate、应用结果
3. 给工作台和写作包提供稳定上下文

所以更准确地说：

- **文件**：保存作品内容
- **协议**：保存当前流程状态
- **数据库**：保存结构化世界状态和结构化知识状态
- **上下文包**：保存当前运行时最小工作集

## 我现在是怎么工作的

我现在不是直接对数据库写小说。

实际顺序是：

1. 先读作品文件
   - 设定
   - 大纲
   - 正文
   - 本书写作卡

2. 再读协议
   - 当前哪本书
   - 当前哪一卷哪一章
   - 当前批次目标

3. 必要时读数据库读模型
   - 角色状态
   - 待处理项
   - 复盘结果
   - 候选经验 / 已激活规则

4. 然后产出内容
   - 设定
   - 大纲
   - 正文
   - 复盘
   - 结构化知识对象

5. 定版内容优先落回文件
   - 不是直接把聊天内容塞进数据库
   - 而是先落到 `books/...`
   - 再由同步链和知识链吸收结构化信息

## 当前推荐用法

### 日常创作

1. 在 `VSCode` 里和 Codex 讨论或直接写
2. 定版后把内容落到 `books/作品名/`
3. 再用网页工作台查看作品
4. 只处理少量高风险或例外项

### 当前工作区目录

```text
books/
  末站执灯人/
    book.yml
    00-设定/
    01-大纲/
    02-正文/
    03-中间产物/
```

注意：

- 只定目录，不定磁盘
- 无论项目在 `F:`、`D:` 还是别的盘，都按“相对工作区根目录”理解

## 核心命令

### 启动网页

```powershell
npm.cmd run dev:web
```

### 启动 Worker

```powershell
npm.cmd run dev:worker
```

### 检查中文编码

```powershell
npm.cmd run encoding:check
```

### 协议链 smoke

```powershell
npm.cmd run db:protocol-smoke
```

### 同步链 smoke

```powershell
npm.cmd run db:sync-smoke
```

### 数据层检查

```powershell
npm.cmd run db:check
```

### 生成迁移

```powershell
npm.cmd run db:generate
```

### 当前批次正文元语言检查

```powershell
npm.cmd run writing:meta-check -- --dir books/作品名/02-正文 --from 起始章号 --to 结束章号
```

### 当前作品字数预算检查

```powershell
npm.cmd run writing:budget-check -- --book-root books/作品名
```

如果当前章均字数已经撑不起这卷的目标字数和目标章数，这条命令会直接提示：

- 当前章均字数是多少
- 按当前章均继续写，整卷大概只能写到多少字
- 如果保持当前章均，应该把卷章数改到多少
- 下一步应该“提高单章字数”还是“先重规划再继续写”
