# 通用写作卡模板

这份模板不是“固定写法脚本”，而是写长篇时的稳定因子模板。

原则只有一句话：

**模板只管方向，不管句子。**

也就是说，它用来约束：
- 作品气质
- 角色声音
- 节奏规律
- 禁忌表达

它不应该把正文写成机械流水线。

## 1. 作品文风基线

### 作品气质
- 这本书整体给人的第一感觉是什么：
- 情绪温度偏冷 / 偏热 / 偏压抑 / 偏轻快：
- 是否允许明显抒情：

### 句子策略
- 短句 / 中句 / 长句哪一种为主：
- 哪类场景可以放长句：
- 哪类场景必须收短：

### 意象系统
- 本书常用意象：
- 本书不该频繁出现的意象：

### 旁白原则
- 解释多少：
- 总结多少：
- 旁白更偏观察 / 判断 / 情绪：

## 2. 主角声音卡

### 看世界的顺序
- 主角遇事先看什么：
- 先看代价 / 先看危险 / 先看关系 / 先看利益：

### 情绪表达方式
- 直接说出来 / 憋着 / 转成动作 / 转成讽刺：

### 说话特点
- 句子长短：
- 用词干净还是带刺：
- 是否爱解释：

### 不可跑偏的核心
- 主角绝对不会轻易做的事：
- 主角最容易暴露出来的本能：

## 3. 配角与关系声音卡

每个关键配角至少写这 4 项：

### 角色名
- 表面状态：
- 说话方式：
- 和主角互动时的张力：
- 绝对不能写成什么味道：

## 4. 章节推进规律

这部分写的是“本书章节一般靠什么往前推”，不是死模板。

- 前段通常解决什么：
- 中段通常引入什么：
- 后段通常逼出什么：
- 章末通常留下什么：

## 5. 章节功能类型库

长篇不是每一章都只负责“硬推主线”。

建议至少从下面这些功能里给章节定性：

### 主推进章
- 推主线
- 出大冲突
- 抛新规则或新秘密

### 过渡章
- 消化上一章后果
- 调整局面
- 给下一次升级做准备

### 关系章
- 人物试探
- 立场变化
- 裂痕、结盟、误会、对账

### 日常章
- 落地世界质感
- 长人味
- 让角色在不打仗时也成立

### 信息章
- 交代规则
- 放传闻
- 补背景
- 让读者理解局势变化

### 回收章
- 把前文埋下的点兑现
- 给读者满足感
- 同时给后续留下新问题

## 6. 张弛节奏原则

默认不要一路硬推。

可参考的基础节奏：

- `2-3` 章推进
- `1` 章过渡 / 关系 / 日常
- 再进入下一轮升级

这不是死规则，但能避免整本书变成事件流水线。

## 7. 禁忌表达清单

把这本书最容易写出 AI 味、空话味的东西直接列出来。

- 不要频繁出现的比喻：
- 不要反复出现的总结句：
- 不要滥用的情绪词：
- 不要写成的类型腔调：

## 8. 写前速看清单

每次写正文前，至少看这几样：

1. 作品定位
2. 当前卷大纲
3. 当前章目标
4. 主角声音卡
5. 关键配角声音卡
6. 禁忌表达清单

## 8.1 开写前门禁

正式进入某一卷正文之前，至少要先完成：

1. 整卷功能和卷末兑现点
2. 分阶段骨架
3. 当前卷章节功能配比
4. 过渡章、关系章、日常章的位置预留
5. 当前批次详细章纲

如果上面这些没定住，就先补规划，不直接开写。

## 9. 写后复盘与知识沉淀

每写完 `3-5` 章，建议做一次轻复盘。

复盘时把内容分成三类：

### 升级到通用层
- 适合所有长篇复用的规律
- 例如信息释放节奏、章节功能比例、章末逼迫方法

### 写回本书层
- 只属于这本书的文风、人物声音、关系推进方式

### 标记废弃
- 看起来像规则，但实际会把正文写死或写偏的东西

## 10. 使用说明

正确用法：
- 写前先看一遍
- 落笔时当成潜规则
- 写完后用来检查有没有跑偏

错误用法：
- 逐条照抄
- 按顺序强行套段落
- 为了“像模板”牺牲人物自然度

## 11. 元语言阶段说明腔禁忌

这类表达默认禁止直接写进正文：

- “卷一后半段……”
- “卷末真正要做的是……”
- “第四阶段开始以后……”
- “整本书到这里……”
- “下一组 / 下一阶段……”

原则：

- 正文只能写角色当下能看到、能判断、能说出口的东西
- 章节规划、阶段总结、作者复盘只能留在大纲、复盘或协议文件里
- 不允许把创作管理语言直接塞进正文

## 12. 写后即时扫描

每次写完当前批次正文，不要等全卷结束再回扫。

固定执行：

```powershell
npm.cmd run writing:meta-check -- --dir books/作品名/02-正文 --from 起始章号 --to 结束章号
```

作用：

- 及时扫出“卷一 / 卷末 / 阶段 / 整本 / 下一组”这类元语言阶段说明腔
- 把问题控制在当前批次内解决，避免后面全局返工

## 13. 字数预算校正

长篇规划不能只看“大纲想写多少章”，还要看“实际一章能写出多少字”。

每批正文写完，除了扫元语言，还要做一次字数预算检查：

```powershell
npm.cmd run writing:budget-check -- --book-root books/作品名
```

检查目标：

- 当前章均字数是否仍然落在目标区间
- 按当前章均继续写，本卷 projected volume words 是否还能支撑当前分卷计划
- 如果 projected total 和目标体量偏差过大，就先重规划，不再盲目往后写

原则：

- 章数字不是定死的，应该按真实产能动态校正
- 但也不能无限放任“越写越短”
- 如果想保住原本的卷体量，就要把后续章节提升到目标字数
- 如果当前写法就是更短，就应及时扩章或重算分卷，不要等卷末才发现账对不上

## 14. 规划 / 执行 / 验证原则

这三条不是句子模板，而是默认工作流规则。

### 14.1 先规划再写

- 先定整卷功能、阶段事件、章节功能配比，再开正文
- 先定当前批次详细章纲，再写当前批次
- 没有整卷骨架和当前批次章纲，不直接靠临场发挥硬写

### 14.2 先验证再算完成

- 当前批次写完后，先跑检查，再宣布完成
- 至少完成：
  - `writing:meta-check`
  - `writing:budget-check`
- 在需要更新协议、复盘和知识状态时，再补：
  - `encoding:check`
  - `db:protocol-smoke`

### 14.3 先查根因再决定重写

- 发现问题后，先判断问题属于哪一类，再决定动作
- 默认分类：
  - 规划缺口
  - 承接断裂
  - 信息锚点不足
  - 节奏失衡
  - 字数预算失衡
  - 执行层 bug
- 没有根因分类，不直接重写正文或重排分卷

## 15. 开篇锚点与承接规则

这部分处理的不是文风，而是“读者能不能顺着看下去”的基础阅读问题。

### 15.1 重要人物首次出场规则

重要人物第一次正式进入戏里时，至少要给出下面 3 项里的 2 项：

- 他是什么身份 / 职位
- 他对主角有什么现实压制力或现实帮助
- 主角为什么认识他、怕他、烦他、欠他

不要求长篇背景说明，但不能只让角色知道、读者不知道。

### 15.2 重要地点 / 组织首次出现规则

重要地点、组织或秩序词第一次正式出现时，至少要交代：

- 它是什么
- 它为什么重要
- 它和主角当前生活的关系

悬疑可以后置真相，不能后置基础理解。

### 15.3 章尾钩子与次章承接规则

- 章尾抛出的现场问题，次章开头必须先接住
- 如果次章要切到新场景，必须先交代上一章钩子的当场后果
- 不允许用“直接跳到第二天 / 直接切别处”来冒充留白

断场不是伏笔。只有“当前因果成立、后续继续扩展”才算伏笔。

### 15.4 认知分层规则

写悬疑时要明确分清：

- 读者现在知道什么
- 主角现在知道什么
- 其他角色现在知道什么

如果角色说一句带旧事、带组织、带地点的话，会导致读者产生基础理解断层，就要补最低限度的支点。

### 15.5 开篇 10 章最低要求

前 10 章至少要完成这些事：

- 让读者知道主角靠什么活
- 让读者知道眼前主要压制力量是谁
- 让读者知道主要舞台分层是什么
- 让读者知道当前异常为什么会改变主角人生
- 至少完成 1 次“小问题 -> 追查 -> 后果 -> 小兑现”的闭环

如果这些没完成，不能继续往后堆谜团。
